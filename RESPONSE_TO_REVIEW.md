# Response to the MathWorks review

This document maps each item of the MathWorks review to the commit that addresses it and the files that changed. All numbers quoted here come from the saved outputs in `results/`; the README's Reproduce section gives the command for each one. Commits are on branch `review-response`, and the release is tagged V1.3.

## Finding added during the audit: OASBUD labels were inverted

The audit found a problem the review did not mention. Every OASBUD consumer treated `class == 0` as malignant, but the file has 48 class-0 and 52 class-1 records, matching the 48 benign and 52 malignant lesions reported for OASBUD. The BI-RADS field agrees: 31 of the 48 class-0 records are BI-RADS 3, and 50 of the 52 class-1 records are BI-RADS 4b, 4c or 5. The OASBUD training PNGs therefore had swapped labels, and every earlier OASBUD accuracy was scored against inverted ground truth. The MATLAB side was fixed in 9688c35 (`Phase4_OASBUD_Export.m`, `Phase6_CNN_Evaluation.m`, `Phase5_BeamformingImproved.m`, `OASBUD_loading.m`) and the Python side in e0f8ea7 (`Holoscan/data_source_op.py`, `output_op.py`, `Phase6_Pipeline_Benchmark.py`). Every result below was produced after the fix.

## Dataset integrity and CNN retraining

The unrecoverable test partition is addressed in 9688c35. `MATLAB Codes/buildCombinedDatastore.m` is now the only loader for the five datasets, including the BrEaST mask and label filtering, and both `Phase4_MegaTrain.m` and `Phase6_CNN_Evaluation.m` call it. `Phase4_OASBUD_Export.m` chooses the first 20 patients of each class from the loaded class field, uses `imageDataAugmenter`, and checks every file it writes against its label; it also writes a manifest of exported patients. Training performs one 70/15/15 split, stratified by class and grouped by patient, and saves the keys and seed to `MATLAB Codes/cnn_split.mat`. Evaluation loads that list and asserts that it does not overlap training. The code now uses `trainnet`, `imagePretrainedNetwork`, `minibatchpredict` and `crossentropy`, with a single malignant weight of 1.5. The model was retrained (seed 42, 30 epochs, train 3080, validation 721, test 636 images; `results/training_log.txt`). On the true hold-out test set it reaches 81.76% accuracy, malignant AUC-ROC 0.9105 and AUC-PR 0.8154, with per-class metrics and the confusion matrix in `results/cnn_eval.md`. The ONNX export has input `input_1` and output `Logits_softmax`, and MATLAB and ONNX Runtime agree on the predicted class for all 10 bundled tiles (`results/logs/onnx_parity.txt`). The earlier 87.37% figure is no longer reported anywhere.

## Pipeline accuracy and preprocessing

The pipeline benchmark change is in e0f8ea7. `Holoscan/data_source_op.py` and `Phase6_Pipeline_Benchmark.py` now score only the 60 OASBUD patients that were not used for training, read from `cnn_split.mat`. Pipeline accuracy on them is 55.0% (33/60); an all-records run is available but its output says it includes training patients (68.0%). For preprocessing, min-max renormalisation was removed: the pipeline, the MATLAB evaluation and the training export all scale the B-mode straight to uint8. The benchmark previously had its own copy of the enhancement step with no filter and a 3-class argmax; it now calls the operator functions. MATLAB Section 9 on the same patients gives 56.7% (34/60). `DEMO_RUN_COMMANDS.md` now lists the pipeline figure and the MATLAB CNN figure on separate labelled lines; that change is in the release commit.

## Enhancement filter selection

This is addressed in 9eb9da8. `MATLAB Codes/Phase3_Enhancement.m` is now a function with no workspace prerequisite. It scores the filters on real data with CNR, generalised CNR, speckle SNR and an edge gradient ratio, using fixed ROIs written in the code. It also scores them on a synthetic phantom with `imnoise` speckle at three variances, using PSNR, SSIM and gradient correlation against the clean phantom. By the selection rule fixed in the script, the bilateral filter ranks first (mean rank 1.14), against Wiener 2.14 and median 2.71, so median is no longer deployed. The bilateral filter is now used in `Holoscan/enhancement_op.py` (in e0f8ea7), `HoloscanPlaneWave/enhancement_op.py`, the Simulink Enhancement block and Section 9 of the evaluation. The Python version matches MATLAB `imbilatfilt`. Figures use captured handles, and the summary figure was opened and checked. The results show that median keeps more edge gradient and that Wiener wins at the highest phantom noise level, and the README says so.

## Toolbox usage and Simulink

The toolbox and memory items are in 133716c. `Phase7_PhasedArrayToolbox_RealData.m` adds a 2-D `phased.TimeDelayBeamformer` image over 201 steering angles on the real CIRS040GSE frame, beside the hand-written DAS image (`results/figures/Phase5/toolbox_tdb_vs_das.png`); the custom DAS kernel remains the GPU Coder target and nothing is applied to OASBUD. `Phase5_ReconstructionComparison.m` uses `phased.MVDRBeamformer` in place of `beamform_mvbf.m`, and element positions come from `phased.ULA` and `getElementPosition`. `Phase5_BeamformingImproved.m` accumulates the coherence-factor sums inside the element loop, and its output is identical to before (max absolute difference 0). `frameK(1) = 0` in `fk_migration_planewave_multiangle.m` is kept, because only the (f=0, kx=0) element is undefined; the reasoning is in the commit message and a code comment. The Simulink driver `Simulink/run_enhancement_subsystem.m` is in 9eb9da8. It builds `rf_ts` with shape [nSamples nElements nTime], runs `sim` and asserts the output is finite, correctly sized and not all zero; the README now describes the model as functional and the driver as the way to run it.
